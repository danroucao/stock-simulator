# 提醒中心：架構、設定與限制

第一版為站內每日收盤事件清單，沒有外部通知、即時掃描或自動下單。全市場結果由排程產生，不會在使用者開啟網站時掃描。

## 現有架構與資料發現

- Angular 22 靜態網站，既有 `.github/workflows/deploy-pages.yml` 發布 GitHub Pages。
- Cloudflare Worker 只有 HTTP 行情代理，沒有 KV／D1／排程綁定。為避免另建後端與資源，第一版採 GitHub Actions + JSON。
- 現有 TWSE STOCK_DAY 與 FinMind TaiwanStockPrice 是原始日線 OHLCV。既有 stock-info 代理只保留名稱／代號，無商品／市場別。保留既有流程，掃描獨立取得官方公司清單。
- 掃描公司名冊來自 TWSE `t187ap03_L`、TPEx `mopsfin_t187ap03_O`；只取官方公司名冊中的四位普通股代號。ETF、權證、興櫃及其他商品不混入。
- [FinMind 官方技術文件](https://finmind.github.io/tutor/TaiwanMarket/Technical/)列出還原 OHLCV `TaiwanStockPriceAdj` 及不指定個股的整批日資料，需 backer／sponsor 權限。實際權限以帳號 API 回應為準。
- [官方配額說明](https://finmind.github.io/quickstart/)：一般有 token 為 600 次／小時，無 token 為 300 次／小時。會員配額可能不同。既有 Worker 與排程若共用 token，配額也共用。

## 使用者還需完成的設定

1. 在 GitHub repository secrets 設定 `FINMIND_API_TOKEN`，帳號必須能取得整批 `TaiwanStockPrice`、`TaiwanStockPriceAdj` 與交易日曆。不要把密鑰放前端 runtime-config 或提交到 Git。
2. 確認 Actions 已啟用且允許 workflow 寫入 repository；排程 workflow 需位於預設分支。分支保護需允許掃描 commit；否則必須改為其他持久化／發布管線。
3. 既有 Pages workflow 仍需 repository variable `TPEX_PROXY_URL`、Pages environment 與發布權限。
4. 檢查資料授權是否允許公開發布衍生結果／最近 100 日還原走勢；若不允許，應改用受保護後端。這項是部署前的實際資料使用限制，程式不會代為申購會員。
5. 第一次啟用手動執行 `Scan Taiwan ordinary stocks after close`，保留 `publish=false`（預設），先檢查 Actions Summary 的成功狀態、交易日、涵蓋數與排除數。驗證模式不 commit、不部署，產生的 JSON 僅留在暫時 runner，不公開上傳行情檔案。這次開發沒有觸發遠端 workflow、上傳密鑰或發布網站。
6. 取得正式發布授權後，才使用 `publish=true`，並將 repository variable `MARKET_SCAN_PUBLISH_ENABLED` 設為字串 `true` 啟用每日排程。未設定該變數時定時工作會跳過；手動驗證仍可執行。注意：既有 Pages workflow 會在推送 main／master 時部署，驗證模式不會阻止另一個 workflow 的這項行為。
7. 掃描程式、規則或工作流程推送到 main 時也會自動執行只驗證模式，讀取 GitHub Secret，檢查真實 API，但不寫回市場結果或觸發第二次 Pages 部署。

## 排程與持久化

`scan-market.yml` 於週一至週五 UTC 11:20（Asia/Taipei 19:20）執行；GitHub 排程可能延遲。實際行情日以來源交易日曆與資料日期判斷，不以執行日期冒充交易日。非交易日仍可取得最近交易日，不產生重複事件。

`node scripts/scan-market.mjs`（Node 24）不依賴瀏覽器、Worker 或 npm 套件。每次重新取得最近 100 個交易日的原始與還原整批資料，約 203 次 API 請求，硬性預算 260 次；串行執行，30 秒單次 timeout，5xx 最多重試兩次，權限／402／429 立即停止。每日期至少 80% 公司名冊覆蓋，否則整次失敗並保留舊結果；個股缺漏、停牌、零成交、低流動性會排除。這個 80% 是防大量資料遺失的工程門檻，仍須監看排除數。

成功狀態保存於 `scan-data/state.json`，事件與快照保存於 `public/alerts/latest.json`。兩檔在同一 Git commit 發布，push 失敗就不發布。失敗只更新公開狀態／嘗試時間，不修改上次成功日期、結果或掃描狀態。GITHUB_TOKEN 的 commit 不會觸發一般 push workflow，因此排程明確 dispatch 既有 Pages workflow。資料必須經過既有建置／測試／部署才會出现在 Pages；失敗狀態同樣需要發布成功才可見。

重跑仍顯示當個行情交易日已建立的事件；不是將新增數歸零。初次安裝只建立當日目前符合的觀察快照，不偽造歷史事件。前端使用相對 document.baseURI 的 URL，相容 Pages 的 repository 子路徑，重新讀取採 no-cache；HTTP 失敗保留本次頁面記憶體中的結果。正式資料沒有任何示意股票。

行情歷史不跨掃描日快取：除權息／分割會回溯調整歷史價，直接追加昨日快取可能造成假跌破。第一版用每次重抓 100 日換取一致性；公開 JSON 包含所有公司最近 100 日，資料量與事件歷史會持續成長，後續可拆分個股檔案及事件封存，不能直接丟棄仍使用的區間 anchor。

## 規則與價格基準

參數集中於 `src/app/services/market-alerts.ts` 的 `ALERT_RULES`，初始版本 `tw-daily-v1`，尚未完成策略成效回測。

- 整理：最近 45 **交易日**的 high／low−1 ≤ 15%；收盤價 OLS（x=0…44）斜率 ×44／45 日算術平均收盤，絕對值 ≤5%；SMA60／10 個交易日前的 SMA60−1，絕對值 ≤3%。至少 70 個完整交易日。
- 近 45 日平均成交金額 ≥1,000 萬元，且無零成交日。金額是原始實際成交金額。1,000 萬元僅為降低低流動性雜訊的可調整工程起點，無回測優勢宣稱。
- 區間在辨識日保存上下緣、辨識日、當日原始收盤 anchor、規則版本。持續整理不每天重建；收盤嚴格高於／低於已保存區間才改為突破／跌破，等於上下緣仍在區間。回到區間後再次越界才重新提醒。
- 區間沿用最長 60 個交易日；到期／anchor 缺失後建立失效事件，等待 5 個交易日再辨識。資料排除時凍結狀態，恢復後才再次判斷。規則版本不符時掃描程式拒絕自動覆寫，需維護者备份 state 與 feed、重建狀態，不把新舊版本硬接。
- R=SMA5／SMA60，偏離=(R−1)×100%；R≤0.8 或 R≥1.3 為低／高偏離。首次進入、退出及再次進入建立事件；持續相同狀態不重複。SMA60 方向與 10 個交易日前比較。
- 突破量比：當日原始成交量／**不含當日**的前 20 日平均量；≥1.5 為初始量能觀察門檻，無成功保證。
- 保存快照不覆寫。當前比較用「目前還原資料中 anchor 日的價格 × 當前原始收盤／當前還原收盤／保存 anchor 原始收盤」換算舊上下緣。所有平均／辨識／圖表統一到本次股票行情日的基準。事件保留觸發當時的區間與量比。
- 個股提醒詳情的 SVG 與區間均用還原日線換算至最新股票行情基準；既有 K 線仍是原始日線，沒有將還原區間疊在不同基準的圖上。

## 個人操作

「今日新增」顯示最新行情交易日的新事件／變更，含離開門檻及區間失效。「目前符合」顯示仍在觀察的股票。「我的追蹤」保留不符合或被排除的股票與原因；不再在名冊時提示資料缺漏。事件依股票合併，不建立推薦評分。

追蹤沿用本機 localStorage 架構，獨立 key `stock-alert-follows-v1`，不需要登入，不會同步其他裝置。此追蹤代表提醒清單關注，與既有行情快取「股票記錄」分開；查看個股沿用既有取得行情與保存個股記錄的行為。現有 workspace 匯出／匯入尚不包含提醒追蹤。瀏覽器儲存失敗會顯示錯誤且不假裝成功。

詳情入口保留事件快照，顯示狀態／成交量／均線。建立模擬交易帶入既有表單股票与提醒來源備註，不提交交易；價格、數量與停損由使用者確認。切換股票沿用既有表單重設行為。

前端過期判斷沿用專案交易日曆（目前已核對 2026 年）；20:00 台北時間之後期待當個交易日，之前期待前一交易日。未核對年份顯示限制，不冒充確知最新交易日；遇臨時全市場停市，可能暫顯示落後提示，需更新前端日曆。

## 驗證

`npm test -- --watch=false`：整理三條件、門檻邊界、資料不足／異常／缺漏／零成交／低流動性、昨日區間突破、排除當日均量、重跑去重、回到原區間／再次突破／跌破、快照保留、分割換算、均線進出／再次觸發、區間失效／冷卻、追蹤持久化、失敗保留與假日過期判斷。

先啟動 `npm start`，再 `node scripts/verify-alert-center.mjs`：1280px／390px 搜尋、市場篩選、追蹤後重載、快照詳情、模擬来源、無新增／仍符合、失敗／過期呈現與手機溢出。瀏覽器測試資料僅在 Playwright 攔截，絕不寫進 public。畫面截圖在忽略的 tmp/。

`node scripts/verify-scan-pipeline.mjs`：在隔離 tmp 目錄以攔截 HTTP 的 1,001 檔測試名冊執行真正的掃描程式，驗證整批資料、状态持久化、重跑去重、配額與行情覆蓋不足時保留成功結果。這是離線整合測試，不能代替真實密鑰權限及上游服務驗證。
